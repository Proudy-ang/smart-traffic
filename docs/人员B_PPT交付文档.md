## 二、三大核心模块

### 模块① 交通态势数据算法

**功能**：将 YOLO 的原始计数值转化为工程可用指标

- **EWMA 指数平滑**：α=0.283（τ=3s），消除逐帧抖动
- **密度换算**：排队密度 = 平滑值 / 等待区面积（30m²/车道）
- **流率换算**：瞬时流率 × 60 → 每分钟人/车流量
- **数据质量评分**：0-100，连续无效帧衰减，30秒归零触发降级
- **容错机制**：Hold-Last-Value + 跳变异常检测（单次计数超10倍触发告警）

**输出**：[人员A 配时用] vehicle_flow_rate（辆/分钟）、data_quality（可信度）

### 模块② 闸机安全风控

**功能**：8 状态状态机，双通道防尾随

```
IDLE → APPROACHING → DECIDING → OPEN → CLOSING → IDLE   (正常通行)
                                  ├→ TAILGATE → ALERT → LOCKED   (异常)
                                  └→ 闯闸检测 (IDLE/CLOSING时PIR意外触发)
```

- **人脸梯段决策**：置信度≥80 放行 / 50~79 放行+记录 / <50 锁定告警
- **双通道尾随检测**：YOLO ≥2人（主力） + PIR 持续 >1.5s（兜底）
- **PIR 消抖**：30ms 窗口，防误触发
- **自动恢复**：LOCKED 状态 10s 后回到 IDLE

**输出**：[UUSIMA] Modbus TCP 控线圈22（闸机开关）

### 模块③ 系统全局状态框架

**功能**：4 级健康状态，事件驱动升级 + 定时器延迟恢复

| 状态 | 含义 | 系统行为 |
|------|------|----------|
| SYS_OK | 正常 | 全部功能正常 |
| SYS_DEGRADED | 降级 | Hold-Last-Value，闸机继续工作 |
| SYS_PARTIAL_FAULT | 部分故障 | 闸机全锁，交通灯切固定周期 |
| SYS_CRITICAL | 严重故障 | 全停，需人工介入 |

- **心跳巡检**：8 个模块槽位，每 3 周期检查一次
- **跳转表驱动**：当前状态 × 事件 → 目标状态，无匹配则保持
- **恢复规则**：DEGRADED 5s 无异常 → OK；PARTIAL_FAULT 10s 正常 → DEGRADED；CRITICAL 不自动恢复

**输出**：[ThingsBoard] 系统健康状态（绿/黄/橙/红四色）

## 三、技术架构

### 主循环调度（100ms 周期）

| 周期 | 动作 |
|------|------|
| 每周期 | 读取 PIR（串口 Modbus RTU）、更新闸机状态机 |
| 每 10 周期（≈1s） | 读取 YOLO JSON、更新交通数据、1Hz 输出 |
| 每 3 周期 | 心跳巡检 |
| 每 50 周期（≈5s） | 5s 综合输出（给云平台） |

### 模块间依赖注入

```
main.py
  ├── YoloReader  (桥接人员A的检测器 + 摄像头)
  ├── PirReader   (串口 Modbus RTU 读传感器)
  ├── TrafficDataProcessor  → sys_state (触发异常事件)
  ├── GateSafetyController  → sys_state + modbus_client
  ├── SystemStateManager
  └── DataOutput  (汇总1Hz/5s输出)
```

### 多合一传感器通信协议

- **接口**：串口 Modbus RTU
- **波特率**：9600, 8N1
- **从站**：0x02
- **PIR 寄存器**：0x04，功能码 03（读保持寄存器）
- **返回**：0=无人，1=检测到人体

## 四、部署架构（Linux 边缘计算套件）

```
[边缘计算套件 Linux]
  ├── 内置摄像头 (V4L2) ──→ YoloReader (调人员A检测器)
  ├── 内置PIR传感器 ──→ 串口 RTU ──→ PirReader
  │
  ├── traffic_data.py ──┐
  ├── gate_safety.py  ──┼──→ Modbus TCP ──→ UUSIMA (闸机 + 红绿灯)
  └── sys_state.py    ──┘
                         └──→ MQTT ──→ ThingsBoard (云端大屏)
```

- 摄像头后端已做 Windows/Linux 自动切换（`sys.platform` 检测）
- PIR 通过串口 Modbus RTU 直连，不依赖网络
- Modbus TCP 连接失败不影响数据采集，闸机控制降级运行

## 七、技术亮点

- **状态机设计**：闸机 8 状态 + 系统 4 级健康，跳转表驱动，逻辑清晰可测试
- **双通道检尾随**：YOLO 人数为主判断 + PIR 时长兜底，单传感器场景做到可靠防尾随
- **梯段人脸决策**：置信度分段处理（≥80 / 50~79 / <50），而非简单的二值判定
- **渐进降级恢复**：事件驱动立即升级、定时器延迟降级，避免状态震荡
- **模块解耦**：依赖注入，每个模块可独立 Mock 测试（76 个 pytest）
- **跨平台兼容**：摄像头后端自动适配 Windows/Linux，串口路径可配置
- **假数据生成器**：无需真实硬件和 AI 模型即可独立开发调试
